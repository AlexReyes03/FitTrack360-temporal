# AGENTS.md · Reglas de ingeniería para FitTrack360
- Mapa: fit_track_360/ (Flutter/MVVM), fit_track_api/ (NestJS/Prisma/PostgreSQL), docs/ (decisiones). [A-01]
- Verificación: ejecute 'pnpm run lint && pnpm run format:check && pnpm run typecheck:api' antes de commit. [Sensor: pre-commit, C-04]
- Pruebas API: ejecute 'pnpm --dir fit_track_api run test'; prohíba debilitar o borrar tests. [Sensor: Jest, C-05]
- Pruebas Móvil: ejecute 'cd fit_track_360 && flutter test'; sincronice textos UI con tests. [Sensor: flutter test, C-05]
- Ramas: trabaje en 'feat/*', 'fix/*', 'docs/*', 'chore/*'; jamás haga commit ni push a main. [Sensor: pre-commit/pre-push, C-01]
- Commits: aplique formato '<type>(<scope>): <mensaje>' imperativo con scope descriptivo. [Sensor: commit-msg, C-02]
- Revisión: todo cambio entra por Pull Request hacia main con aprobación de al menos un par. [Guía: revisión en PR, C-03]
- Aislamiento (S4): responda HTTP 404 (nunca 403) ante recursos de otro userId para evitar IDOR. [Sensor: Jest auth/meals, A-03]
- APIs externas: consulte USDA FDC solo mediante proxy NestJS con timeout de 5s; jamás desde Flutter. [Guía: arquitectura proxy, D-02, I-01]
- Nutrición: copie y congele macros en MealItem al persistir; garantice inmutabilidad histórica. [Guía: persistencia, M-02]
- Validación: valide DTOs con ValidationPipe whitelist en API y formularios en Flutter. [Sensor: class-validator, C-04, F5]
- Bugfix: todo defecto reportado debe incluir una prueba automatizada que prevenga su regresión. [Guía: sin sensor automático aún, C-05]
- Base de datos: use 'pnpm dev' y valide puertos 5432/3000 antes de levantar contenedores. [Guía: lección aprendida dev-menu]
- Bitácora IA: registre prompts y ajustes en docs/ia/bitacora.md sin subir secretos ni datos sensibles. [Guía: sin sensor aún, Nivel 4 IA]
- Documentación: consulte docs/specs/ antes de proponer y registre decisiones nuevas en sus tablas. [Guía: proceso docs]
- Sensores activos: Husky (pre-commit, commit-msg, pre-push), oxlint, Prettier, dart format/analyze, tsc y Jest. [Sensor]
- Sin sensor aún: regla Bugfix con test previo, bitácora IA y proxy USDA exclusivo en NestJS. [Auditoría manual en PR]
- Nunca: suba secretos/env, salte hooks con --no-verify, use print/console.log en producción ni push a main. [Sensor: husky, I-02, C-04]
- El **título del PR** debe usar el mismo formato que los commits: `<type>(<scope>): <mensaje>`. Así, con squash and merge, el historial de `main` queda limpio y consistente.
- En la descripción del PR incluye siempre `Closes #<número_issue>` para que GitHub cierre el issue al mergear.
